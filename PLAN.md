## Audience and Goal

My main audience is hiring managers and recruiters looking for entry-level web development or IT candidates.

I want my portfolio to show what I have built, what technologies I have used, and what I personally contributed to each project.

## Comparing Two Approaches

**Approach A: Project-focused portfolio**

This design uses a simple homepage with project cards, an About section, skills, and links to my GitHub, LinkedIn, and résumé. Visitors can quickly find my work and see the evidence behind it.

**Approach B: Résumé-focused portfolio**

This design puts education, skills, and experience first, with projects farther down the page. It provides more background but may require visitors to scroll more to find my work.

**Decision:** I chose Approach A because I want employers to find my projects quickly. I can still include my résumé and background without making the website too complicated.

## React Documentary Connection

One idea discussed in *React.js: The Documentary* is how React makes it easier to organize and update website interfaces using reusable components.

For my portfolio, I could use a React component called `ProjectCard` to display each project. Each card would follow the same layout but show different information, such as the project name, description, technologies, and repository link.

This would help me keep the website consistent and make it easier to add projects later.
